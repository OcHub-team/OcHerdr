# Shared UI integration · 2026-10-14

OcHerdr and OcHub now use ochub-ui 0.8.0 at `04567c1bb54a65257577a8f5c21875144914b137`, GPUI at `66519810e58c849d2acf93e1930086390a9bcb22`, and Rust 1.98.1. The shared GPUI branch keeps the existing Display P3 surface support and the macOS 26+ window-material fix.

## Ownership

- `ochub-ui::text_input` owns native editing, Unicode selection, composition guards, plain-text paste, undo, and Find. The local `text_input` module is now a compatibility re-export instead of a complete component fork.
- `ochub-ui::shortcuts` owns platform binding definitions and labels, key-release pairing, shortcut-hint motion, and accessible help rows.
- OcHerdr owns command meaning, prefix actions, terminal focus, and endpoint input. Unhandled terminal keys retain their terminal meaning.
- Shortcut help uses the shared modal focus scope. Search and Close stay in place when filtering. A help request cannot replace an open editing form.
- Notification details consume shell shortcuts and the release event of the Escape key that closes the layer. Their copy button cannot begin a terminal selection underneath.
- Empty session and empty tab views retain the shell focus handle, so keyboard help works before a terminal is connected.

## Validation

The workspace passes 512 tests with 3 ignored integration tests. Clippy passes with `-D warnings`. The notification regression first failed on Ctrl+B leaking into the terminal prefix state and now passes. The help regression dispatches the actual platform shortcut and checks that filtering preserves the search-field bounds.

Native macOS acceptance uses `target/qa/OcHerdr.app` and an independent `OCHERDR_CONFIG_DIR`. It covers the shortcut reference, Chinese filtering, selection replacement, word deletion, undo, Escape, and the 960-pixel window layout. No production session is changed. Screenshots and the joint dependency record live in OcHub's `docs/JOINT-UI-ITERATION-2026-10-14.md`.
